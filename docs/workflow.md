# **🧬 Bio-Edu Suite AI開発マスター・ワークフロー v5.15 (純粋統合版：トライコア運用・ローカル要塞v38.0対応・早期損切りSOP)**

本ワークフローは、「Web版Gemini（戦略・仕様策定・統括アーキテクト）」と「VS Code上の Cline（現場職人 / Actモード）」を連携させた開発環境のためのSOP（標準作業手順書）である。

複数ファイルや全14アプリにまたがる保守・改修において、AIの直接多重編集によるトークン枯渇やコンテキスト破綻を完全に防ぐため、「Pythonスクリプト駆動型ハイブリッド一括更新（手動コピペ実行［第一推奨・完全0円］＆ Cline無人代行）」を唯一の標準作業手順（SOP）として定義する。

AIを「職人的な専属リードエンジニア 兼 シニアUI/UXデザイナー」として機能させ、「破壊なき進化（Zero-Modification）」「コードの目減り防止」「日本学術会議2025年版への完全準拠」を絶対の目的とする。

## **🏛️ 第1章：体制と役割分担 (Architecture & Roles)**

本開発環境では、AIの役割を「司令塔」と「現場職人（Cline）」に完全分離し、ハルシネーションと意図せぬコード破壊（Zero-Modification違反）を物理的に防ぐ。

### **1. 🧠 司令塔（統括アーキテクト / Web版 Gemini）**
* **役割**:
  * 要望の分析とアーキテクチャ設計。
  * 日本学術会議『高等学校の生物教育における重要用語の選定について（2025年版）』への厳格な準拠チェック。
  * Pythonスクリプトの設計・仕様策定と、Cline向け「単一実行指示書」の生成。
  * 実行ログの解析とリカバリー策の策定。
* **【Web側デュアル／トライコア運用規格（4 Argon 対応）】**:
  * **前衛頭脳（日常・UI/UX調整・指示書生成）**: `gemini-3.8-flash`（または `4 Argon` 標準）
    ユーザーの直感的な意図や文脈をブレなく抽出し、高速かつ高精度にCline指示書へ変換するメインエンジンとして運用する。
  * **後衛頭脳（深淵設計・数理モデル・原因不明バグ解析）**: `gemini-3.1-pro-preview`（または `4 Argon 思考レベル：高値`）
    複雑な量的遺伝学・統計数理モデル（ダイアレル分析等）の新規アーキテクチャ設計や、スタックトレースから根本原因を突き止める難解なトラブルシューティング時のみ特例召喚する。
  * ※「Web側は常にProに固定」という旧規定は廃止する。
* **禁止事項・出力規律**:
  1. 実際のアプリ用のHTML/JSコード全文をWebチャットで直接出力させない。必ず「Clineを動かすための単一実行指示書（または100%完成形Pythonスクリプト）」を出力する。
  2. **【勇み足出力の絶対禁止】**: ユーザーから対象アプリの最新コード（または該当箇所・骨格）を受け取る前に、Cline実行指示書（実装プロンプト）を出力してはならない。構想・設計合意を先に行い、コード受領後に初めて指示書を作成する。
  3. **【ワンクリックコピペ用コードスニペット化原則】**: Clineへ投入する指示書部分（実装指示、ガイドライン改訂指示、Python一括改修指示、リカバリー指示）は、ユーザーがWeb画面のコピーボタンからワンクリックで複製できるよう、必ず独立した単一のコードブロック（```text ... ``` または ```python ... ```）として出力すること。前後の解説文をコードブロック内に混入させてはならない。
  4. **【動作検証デモデータ＆確認手順の同時出力義務】**: 新機能の追加やUI・ロジックの改修指示書を発行する際は、ユーザーが即座にLive Server等で受け入れテストを実施できるよう、指示書とセットで必ず「外部投入用の確認用デモデータ（生物学的妥当性を備えたFASTA/Newick/TSV/JSON等）」および「具体的な確認手順・期待動作チェックリスト」を出力すること。
  5. **【検証結果に応じたネクストアクション3分岐の同時出力義務】**: 出力するすべての指示書（デモデータ・確認手順）の直下には、ユーザーが検証を終えた後の次の行動に迷わないよう、「✅ Case A（完全動作・Commit & Push）」「⚠️ Case B（不具合・生ログ丸ごとフィードバック）」「🛑 Case C（崩落・git restoreによる白紙撤回）」の3分岐判定ブロックを必ずセットで出力すること。

### **2. 🛠️ 現場職人（VS Code拡張機能：Cline）**
* **実行責務**:
  * **単一・少数ファイルの局所修正（1〜2箇所）**: 直接編集（Actモード / 差分適用）。
  * **単一ファイル3箇所以上の修正 または 複数アプリの一括改修（全14アプリ等）**:
    1. **ルート①（手動コピペ実行・第一推奨・完全0円）**: 司令塔が出力したPythonスクリプトをユーザーが `scripts/update_XXXX.py` に保存し、ターミナルで直接実行する。
    2. **ルート②（Cline無人代行）**: Cline（Level 0: `gemini-3.6-flash`）が `scripts/update_XXXX.py` を作成・実行し、`git diff` 検証後に `python3 scripts/cleanup_audit.py --apply` でアーカイブ退避する。
* **モデル段階的エスカレーション基準（Level 0〜4）とファストフェイル運用**:
  * **Level 0（標準無人巡航）**: `gemini-3.6-flash`（リカバリー試行は最大1回に制限）。
  * **Level 1〜2（ファストフェイル昇格・高速推論）**: `gemini-3.8-flash`。1回のパッチ適用でエラーが解決しない場合、または長考ループの兆候がある場合は、トークン浪費を防ぐため即座に `gemini-3.8-flash` へ昇格し、決定力をもって一撃で完了させる。
  * **Level Local（完全オフライン・APIレート制限時の特例安全弁）**: `Ollama` (`qwen2.5-coder:32b`)。1ファイル・1関数のマイクロタスクに限定して運用する。
    * **【Level Local 運用ライフサイクルSOP（司令塔による案内義務）】**:
      1. 【起動】Macのターミナルを開き `ollama serve` を実行（ウィンドウを最小化して放置）。
      2. 【接続】Cline設定で Provider: `Ollama`、Model ID: `qwen2.5-coder:32b` を指定し、チャットをClearしてタスク投入。
      3. 【停止】作業完了後、ターミナルで `Ctrl + C` を押してサーバーを安全停止し、ウィンドウを閉じる。
      4. 【復帰】Cline設定で日常巡航モデル `Google Gemini (gemini-3.6-flash)` へ戻し、チャットをClearする。
  * **Level 3（Web側司令塔専用・Cline割当禁止）**: `4 Argon (思考レベル：高値)` / `gemini-3.1-pro-preview`。
  * **Level 4（緊急外科手術）**: **Cline + Anthropic API**（`Claude 3.7 Sonnet` / 新規チャット・単一ファイル・外科手術限定・完了後即時Level 0復帰）。
    * **【雪だるま式課金の物理遮断（必須）】**: 上位モデル（Level 4等）へ切り替える際は、肥大化したコンテキストによるトークン浪費を防ぐため、**必ず直前のClineチャット履歴をClear（新規タスク作成）**してから極小の単一指示を与えること。

## **🛡️ 第2章：AI開発・品質保証の運用防壁規格**

### **1. ワンショット・コンテキストリセット原則**
* **履歴蓄積の禁止**: 1回の指示（Step）の完了・検証が完了するごとに、必ずチャット履歴をクリア（Clear）すること。
* **リカバリー継続時の例外**: エラー対応や修正パッチ適用を継続する間（Case B）は、コンテキスト保持のためWeb側・Cline側ともにチャットを維持する（ただしClineがLevel 0で1回失敗した場合は `gemini-3.8-flash` へ昇格させる）。タスク完了時（Case A）または白紙撤回時（Case C）に初めてClearを実行する。

### **2. 終着点アプリの完全空箱化と手動バケツリレー原則**
* **個別アプリの空箱死守**: 解析アプリ（⑤〜⑭）内に、テスト用・デモ用のボタンや固定プリセットデータを内包させることを固く禁じる。
* **ダッシュボードのLIMS役割と手動バケツリレー**: ダッシュボード（アプリ①）は未処理の生データ（サンガー波形、塩基配列、画像、環境メタデータ）を保管するデジタル野帳（LIMS）とし、各解析アプリ間は生徒自身の「コピー＆ペースト」または「ローカルファイル保存＆ドロップ」による手動バケツリレーで連携させる。

### **3. QA・導通確認のUI非侵食原則**
* **開発用UIの排除**: 導通確認や動作検証を目的とした安易なボタンやトグルを本番UI上に配置してはならない。
* **検証セットの同時出力**: 新機能や改修の検証は、司令塔が指示書と同時に出力する「検証用デモデータ」の手動貼り付け、または `scripts/` 配下の単体テストスクリプトによって担保する。

### **4. 2段階分離開発プロセス（Model先行・View後続）**
* **Step A (Model & Test)**: まず `lib/bio_math_engine.js` に純粋な計算関数を実装し、テストスクリプト（学術的グラウンド・トゥルースとの突合）で完全なPASSを確認する。
* **Step B (View & Controller)**: テスト通過後、チャットをリセットした上で外箱HTMLおよび `js/*_ui.js` の実装指示へ進む。

### **5. 全11大・トークン極限圧縮＆ハルシネーション物理防止プロトコル**
1. **コンテキストキャッシュ**: 不変のシステム指示書・ガイドラインはキャッシュを活用し反復読み込みを遮断する。
2. **ポインタ参照（差分指定）**: Clineでの全行読込を禁じ、行番号指定または `git diff` のみでパッチを当てる（※Web版Geminiへの初期相談時のみファイル全文の直接貼付を特例許可し、司令塔側で骨格化する）。
3. **前処理・ログ要約（Web側生ログ特例付き）**: Web版Geminiへは生ログ丸ごとの貼付を許可し、司令塔側が核心原因を抽出してCline向け極小指示書へ蒸留する。
4. **厳格モデルルーティング**: Web側デュアル／トライコア（`3.8-flash` / `3.1-pro`・`4 Argon`）、Cline側ファストフェイル（`3.6-flash` → `3.8-flash`）を徹底する。
5. **ワンショット・リセット**: タスク完了ごとにチャット履歴をClearし累積トークンを遮断する。
6. **ソースコードの骨格化**: 設計時は関数実装を省略したインターフェース骨格のみを扱う。
7. **非同期バッチAPI**: 即時性の不要な一括処理はバッチAPI（半額）を活用する。
8. **プロンプトXML化**: 指示書はXMLタグ（`<task>`, `<instruction>`）で高密度化する。
9. **巨大データの切り詰め**: 長大な塩基配列・アミノ酸配列・Base64・JSONは先頭5行・末尾5行＋長さハッシュのみを渡す。
10. **AST関数スコープ抽出**: 複雑な関数修正は構文木単位で切り出し外部への副作用を防ぐ。
11. **ローカル処理連携**: 構文チェックや一括置換はPythonスクリプトやローカルLLMで処理する。

### **6. 受け入れテスト規格（Acceptance Testing SOP / v38.0対応）**
1. **ローカル要塞＆アプリ間往復遷移テスト**:
   * オフライン（未入室）状態でデータを入力・編集または削除し、ドロワー経由で別アプリへ遷移した後に再び元のアプリへ戻る。
   * 通信を一切介さず、`localStorage` / `sessionStorage` / `IndexedDB` から直前の最新状態が100%完全復元され、削除データのゾンビ復活や初期値への巻き戻しが発生しないことを確認する。
2. **コピー＆ローカルファイル保存ペア導通テスト**:
   * データを出力するアプリにおいて、「コピーボタン（二重シート型SVG）」の隣に「ローカルファイル保存ボタン（フロッピー型SVG）」がペアで配置され、ダウンロードしたファイルを次工程アプリの `.drop-zone` へドロップして同一の解析が継続できることを確認する。
3. **オンデマンド手動クラウド同期＆隠れ教師モード導通テスト**:
   * **教員ロール（`TEACHER-*`）での入室**: `#teacherPresetSection` が表示され、任意の課題コード（例: `TASK-01`）で `/master_tasks/{taskCode}` へ教材データを登録・発行できること。
   * **生徒ロール（通常ID）での入室**: `#teacherPresetSection` が完全不可視化されていること。常設の課題読込窓から課題コードを入力して「読込」を押した際、画面と `sessionStorage`（および `.ab1` 波形がある場合は `IndexedDB`）へ即座にハイドレーション展開され、そのままアプリ④等へ波形を送れること。
   * **手動クラウド保存・復元**: モーダル内の「☁️ 現在の作業をクラウドに保存」および「📥 クラウドから作業を復元」ボタンを押した時のみ通信が行われ、別端末・別ウィンドウ間で画像やリッチステート（系統樹、BLAST結果等）が非破壊で完全復元されること。
4. **解析ログ・タイムマシン復元テスト（該当アプリ）**:
   * 異なるパラメータで2回以上解析を実行し、過去のログ行をクリックした際、対象行がボーダーレスのフラット背景色（`#d1f2eb`）でハイライトされ、キャンバス描画およびエクスポートデータ（Newick/TSV等）が過去ステートへ完全再充填されること。
5. **3D複合描画テスト（アプリ⑭等）**:
   * 「半透明表面」モード選択時に外殻（半透明表面）と内部骨格（不透明リボン）が重畳描画され、突然変異部位やリガンドが透過視認できること。

## **🧭 第3章：開発フェーズ別 実行プロトコル (Phase Pre-A 〜 Phase E)**

### **🏛️ Phase Pre-A：大規模改修前の事前法制化と新旧統合 (Rule-First Deployment)**
全14アプリに影響する共通UI、データ構造、用語規格の更新などの大規模改修を行う場合、アプリ実装用プロンプトを発行する前に、必ず先行して `docs/guideline.md` の改訂を実施・コミットさせる。
* **【ゾンビ規定防止ルール】**: ガイドライン改訂時は、廃止・変更された旧規定を残したまま末尾に追記することを禁じ、必ず該当箇所を最新仕様へ上書き統合して矛盾ゼロの状態を保つこと。

### **🧭 Phase A：構想と仕様策定 (Webチャット)**

#### **🤖 プロンプトA-0（構想・議論・ブレインストーミング）**
```text
【役割】あなたはBio-Edu Suiteの厳格なシニアUI/UXデザイナー兼、統括アーキテクトです。
【指示】以下の【テーマ】について、実装やコード出力は一旦保留し、教育的意義や機能の要不要について深くブレインストーミングと議論を行ってください。Cline向けの指示書はまだ出さないでください。
【テーマ】：[議論したい内容を記載]

```

#### **🤖 プロンプトA（仕様策定と指示書の作成）**

```text
【役割】あなたはBio-Edu Suiteの厳格なシニアUI/UXデザイナー兼、統括アーキテクトです。以下の【課題/要望】に対し、同梱の『ガイドライン』および日本学術会議2025年版用語規格に従ってどう解決すべきか仕様案を検討し、対象コード受領後にCline用の『単一実行指示書』を出力してください。
【課題/要望】：[ここに違和感や追加・改修したい内容を記載]

```

### **🛠️ Phase C：単一・少数アプリの局所実装 (1ファイル・1〜2箇所)**

1. Clineを **Actモード**、モデルを **`gemini-3.6-flash`（Level 0）** に設定し、指示書を投入する。
2. 差分（Diff）適用結果とUI・描画ロジックの非破壊を確認し、提供された「確認用デモデータ」で受け入れテストを実施する。
3. 指示書末尾の「ネクストアクション（3分岐）」に従い行動する。
* **✅ Case A (PASS)**: `git add . && git commit -m "..." && git push` で確定し、Web側・Cline側の両チャットを **Clear** して次へ進む。
* **⚠️ Case B (FAIL)**: ターミナル生ログやCline報告書を「丸ごと」司令塔へ提示する。両チャットは **継続** し、ClineがLevel 0で1回失敗した場合は **`gemini-3.8-flash`（Level 1/2）へ昇格**させてリカバリー指示を適用する。
* **🛑 Case C (CRITICAL / 画面崩壊・長考ループ・600kトークン超過)**: 処理完了を待たずに即座にClineの Cancel / Stop ボタンを押す。直ちにターミナルで `git restore .`（必要に応じ `git clean -fd`）を実行して白紙撤回し、両チャットを **Clear** してPythonスクリプト化またはAST局所抽出へ作戦を切り替える。



### **🌌 Phase C-Batch：複数アプリ一括改修 または 3箇所以上の修正（PythonハイブリッドSOP）**

全14アプリ横断修正、または単一ファイル内3箇所以上の修正時は、Actモード直接編集を禁止し以下のいずれかのルートで実行する。

* **ルート①：手動コピペ実行（第一推奨・APIコスト完全0円・最速）**
1. VS Codeで `scripts/update_XXXX.py` を新規作成し、司令塔の完成済みPythonコードをペーストして保存。
2. ターミナルで実行: `python3 scripts/update_XXXX.py`
3. 差分を監査: `git diff` および `git status`
4. アーカイブ退避: `python3 scripts/cleanup_audit.py --apply`


* **ルート②：Cline無人代行実行（半自動）**
1. Clineを **Actモード**、モデルを **`gemini-3.6-flash`（Level 0）** に設定し、`<task type="batch_python_sop">` 指示書を投入。
2. `cleanup_audit.py --apply` の完了まで承認・見届ける。



### **🔄 Phase D：ログ解析とリカバリー・ループ (Feedback Loop)**

不具合発生時（Case B）は、Web側司令塔の現在のチャットを継続し、以下のテンプレートで生ログを丸ごと貼り付ける。

```text
【ログ解析と次なる一手依頼】
Clineの実行結果ログ（またはブラウザコンソールログ）です。現状の分析を行い、日本学術会議2025年版規格およびガイドラインに準拠したリカバリー指示を策定してください。
【実行ログ】：[生ログを丸ごとペースト]

```

### **🔍 Phase E：改修完了後の三位一体ドキュメント監査 (Triad Review)**

アプリの実装・動作検証が完了した時点で、司令塔は作業を終了せず、直ちに以下の3点について運用の齟齬や追従すべき新ルールがないかを自律点検し、ユーザーに提示する。

1. **ガイドライン（`docs/guideline.md`）**
2. **開発ワークフロー（`docs/workflow.md`）**
3. **カスタム指示書（`docs/instruction.md`）**
