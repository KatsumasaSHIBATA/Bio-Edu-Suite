# **🧬 Bio-Edu Suite AI開発マスター・ワークフロー v4.1 (Hybrid Edition)**

本ワークフローは、「Web版Gemini（戦略・仕様策定）」と「VS Code \+ Cline / Aider（実装・自動適用）」を連携させたハイブリッド開発環境のためのSOP（標準作業手順書）です。

AIを「職人的な専属リードエンジニア 兼 シニアUI/UXデザイナー」として機能させ、「破壊なき進化（Zero-Modification）」「コードの目減り防止」「日本学術会議2025年版への完全準拠」を目的とします。

## **🏛️ 第1章：体制と役割分担 (The Hybrid Architecture)**

本開発環境では、AIの役割を物理的に2つに分離し、ハルシネーションと意図せぬコード破壊（Zero-Modification違反）を完全に防ぎます。

1. **🧠 司令塔（Web版 Gemini \+ Canvas）**  
   * **役割**: 仕様の検討、教育的価値の監査、複雑な数学ロジックの設計、ガイドラインの改訂案作成、および実行ログの解析とリカバリー策の策定。  
   * **禁止事項**: 実際のアプリ用のHTML/JSコードを直接生成させない。代わりに「ローカルAIを動かすための指示書」を出力する。  
2. **🛠️ 現場職人（VS Code \+ Cline / Aider）**  
   * **役割**: 司令塔の指示に従い、ローカルファイルを直接読み書きし、差分パッチを適用する。  
   * **モード管理 (Cline)**: .clinerules に定義した擬似モードに従い、Planモード（監査役）と Actモード（実装職人）を切り替えて運用する。

## **🧭 第2章：Phase A \- 構想と仕様策定 (Webチャット)**

新しいアイデアやバグ修正の相談、外部AIからの提案の壁打ちは、Web版Geminiで行います。

### **🤖 プロンプトA（仕様策定と指示書の作成）**

【役割】あなたはBio-Edu Suiteの厳格なシニアUI/UXデザイナー兼、プロジェクトマネージャーです。以下の【課題/要望】に対し、同梱の『ガイドライン』に従ってどう解決すべきか仕様案を検討し、ClineまたはAider用の『実装指示書』を出力してください。【課題/要望】：\[ここに違和感や追加したい機能、または外部AIからの提案内容を記載\]

## **⚖️ 第3章：Phase B \- 法制化とルール同期 (VS Code / Cline)**

Web版の議論で新たなUI規定や用語定義が確立された際は、実装に着手する前に**必ず**マスターファイル（ガイドライン等）への反映・同期を行います。

### **🛠️ 手順**

1. ローカルのClineを起動し、**Actモード**（実装モード）へ切り替える。  
2. Webチャット側で出力された『ガイドライン改訂用指示書』の内容を全コピーして入力する。  
3. Clineから提案される改訂差分を検証・承認し、ガイドラインを最新の状態へ更新する。

## **🛠️ 第4章：Phase C \- 個別アプリの実装と差分適用 (VS Code / Cline)**

最新ルールの同期完了後、具体的なアプリコードの修正フェーズへ移行します。

### **🛠️ 手順**

1. Clineを**Actモード**（書き込み権限有効）に設定する。  
   * ※コード変更を伴わない分析や所在確認のみを行う際は**Planモード**を推奨。  
2. Phase Aで策定された『Cline専用 実装指示書』をプロンプトとして投入する。  
3. Clineによるローカル走査の結果、提示されるDiff（差分）の内容を確認する。  
4. **D3.jsの描画ロジック消失や教育的UIの目減りなど、意図しない破壊がないか目視で厳格に審査し、問題がなければ「Save」で確定させる。**

## **🌌 第5章：広域エコシステムの同期改修 (Aider連携)**

全15アプリを跨ぐ横断的な一括修正（共通フッターの反映や構造定義の変更等）が必要な場合。

### **🛠️ 手順**

1. VS Codeターミナルでaiderを起動する（競合回避のためClineは待機させる）。  
2. Web版Geminiが生成した『Aider用 一括改修プロンプト』を適用する。  
   * 例:\> docs/guideline.md の規定に従い、全15アプリのHTMLヘッダーをフルードレイアウトへ一斉同期して。  
3. 自動実行とGitコミットを確認し、万一の不備があればターミナルで/undoを実行して即座に原状回復する。

## **🔄 第6章：Phase D \- ログ解析とリカバリー・ループ (Feedback Loop)**

ローカルAIからマージ不全やエラーが報告された際、あるいはAiderの実行結果を厳密に評価する際に本プロセスを起動します。

### **🛠️ 手順**

1. ClineやAiderが出力した詳細なエラーログやサマリーをクリップボードにコピーする。  
2. 司令塔（Web版 Gemini）に対し、以下のテンプレートを用いて解析を依頼する。

**【解析依頼テンプレート】**  
ローカルAIの実行結果ログです。現状の分析を行い、次にローカルAIへ与えるべき適切な指示（返信プロンプト）を策定してください。  
【実行ログ】：\[ログの内容をここにペースト\]

3. 提示されたリカバリー案および「次なる一手」の指示文をローカルAIへ再投入し、問題を解消させる。

## **大規模一括改修におけるPython一括更新スクリプト活用の原則（トークン枯渇防止SOP）**

* **背景:** 全15ファイル等の複数アプリ・ファイルに対する直接書き換え指示は、トークン上限の枯渇およびコンテキスト破綻を招く深刻なボトルネックとなる。
* **対策原則（Pythonスクリプト駆動型一括同期）:** 複数ファイルにまたがる一括改修や置換を行う際は、AIに直接各ファイルを多重編集させるのではなく、ローカル環境で安全に動作する「一括更新用Pythonスクリプト」を生成させ、それを実行して同期するアプローチを標準作業手順（SOP）とする。
* **適用手順:**
  1. 司令塔よりPythonスクリプトの仕様とコードを提示・生成させる。
  2. ローカル環境にてスクリプトファイルを配置・実行し、一括置換・同期を行う。
  3. 実行ログを検証し、無限ループやコンテキスト破綻を完全に回避する。

2. **Plan/Actモードの厳格な役割定義**（.clinerulesへペルソナ設定として統合）。  
3. **ガイドラインへの完全準拠プロトコル**（対象パスおよび注視すべき重要項番の明示）。  
4. **一括改修時の安全性担保**（Aiderの具体例と/undoによる迅速なロールバック運用）。  
5. **外部AI提案（セカンドオピニオン）の司令塔処理**（ハイブリッド体制の初期設計思想を明文化）。
