# **🧬 Bio-Edu Suite AI開発マスター・ワークフロー v5.0 (Cline一本化・Pythonスクリプト駆動SOP)**

本ワークフローは、「Web版Gemini（戦略・仕様策定・統括アーキテクト）」と「VS Code上の Cline（現場職人 / Actモード）」を連携させた開発環境のためのSOP（標準作業手順書）です。

複数ファイルや全14アプリにまたがる保守・改修において、AIの直接多重編集によるトークン枯渇やコンテキスト破綻を完全に防ぐため、「VS Code上の Cline（Actモード） ＋ Pythonスクリプト駆動型一括更新（冪等性対応）」を唯一の標準作業手順（SOP）として定義します。

AIを「職人的な専属リードエンジニア 兼 シニアUI/UXデザイナー」として機能させ、「破壊なき進化（Zero-Modification）」「コードの目減り防止」「日本学術会議2025年版への完全準拠」を絶対の目的とします。

---

## **🏛️ 第1章：体制と役割分担 (Architecture & Roles)**

本開発環境では、AIの役割を「司令塔」と「現場職人（Cline）」に完全分離し、ハルシネーションと意図せぬコード破壊（Zero-Modification違反）を物理的に防ぎます。

### 1. **🧠 司令塔（統括アーキテクト / Web版 Gemini）**
* **役割**:
  * 要望の分析とアーキテクチャ設計。
  * 日本学術会議『高等学校の生物教育における重要用語の選定について（2025年版）』への厳格な準拠チェック。
  * Pythonスクリプトの設計・仕様策定と、Cline向け「単一実行指示書」の生成。
  * 実行ログの解析とリカバリー策の策定。
* **禁止事項**: 実際のアプリ用のHTML/JSコード全文をWebチャットで直接出力させない。必ず「Clineを動かすための単一実行指示書（およびPythonスクリプト仕様）」を出力する。

### 2. **🛠️ 現場職人（VS Code拡張機能：Cline）**
* **実行責務**:
  * **単一・少数ファイルの修正**: 直接編集（Actモード / 差分適用）。
  * **複数アプリの一括改修（全14アプリ等）**:
    1. `scripts/` 配下に「多重挿入防止（冪等性）」を備えた Python 処理スクリプトを1ファイル作成。
    2. ターミナルツールで `python3 scripts/XXXX.py` を実行。
    3. `git diff` および `git status` で差分を検証し完了。
* **モード管理**: `.clinerules` に定義したルールに従い、Actモード（差分実装）を基本として安全に運用する。

## **🧭 第2章：Phase A - 構想と仕様策定 (Webチャット)**

新しいアイデアや機能追加、バグ修正、用語改訂の検討は、Web版Gemini（司令塔）で行います。

### **🤖 プロンプトA（仕様策定と指示書の作成）**
```text
【役割】あなたはBio-Edu Suiteの厳格なシニアUI/UXデザイナー兼、統括アーキテクトです。以下の【課題/要望】に対し、同梱の『ガイドライン』および日本学術会議2025年版用語規格に従ってどう解決すべきか仕様案を検討し、Cline用の『単一実行指示書』を出力してください。
【課題/要望】：[ここに違和感や追加・改修したい内容を記載]
```

---

## **⚖️ 第3章：Phase B - 法制化とルール同期 (VS Code / Cline)**

Web版の議論で新たなUI規定や用語定義が確立された際は、実装に着手する前に**必ず**マスターファイル（`docs/guideline.md` 等）への反映・同期を行います。

### **🛠️ 手順**
1. VS Code上のClineを起動し、**Actモード**に設定する。
2. 司令塔が出力した『Cline ガイドライン改訂指示書』を全コピーして投入する。
3. Clineから提案される改訂差分を検証・適用し、ガイドラインを最新状態へ更新する。

---

## **🛠️ 第4章：Phase C - 単一・少数アプリの実装と差分適用 (VS Code / Cline)**

単一または少数のHTML/JSファイルを精密に修正するフェーズです。

### **🛠️ 手順**
1. Clineを**Actモード**に設定する。
2. Phase Aで策定された『Cline アプリ実装指示書』を投入する。
3. Clineによる差分（Diff）適用結果を確認する。
4. **D3.jsの描画ロジック消失や教育的UIの目減りなど、意図しない破壊がないか厳格に検証する。**

---

## **🌌 第5章：複数アプリの一括改修（Pythonスクリプト駆動型一括同期 SOP）**

全14アプリや複数ファイルにまたがる横断的な一括修正（共通UI・ヘッダー・フッター・メタタグの反映や用語の一括置換等）を行うフェーズです。
AIによる多重直接編集によるトークン枯渇・コンテキスト破綻を防ぐため、**Pythonスクリプト駆動型一括更新**を徹底します。

### **🛠️ 手順**
1. 司令塔（Gemini）が策定した『Cline 一括改修指示書（Pythonスクリプト仕様）』をVS CodeのClineに投入する。
2. Clineが `scripts/` 配下に「多重挿入防止（冪等性）」を備えた処理スクリプト（例: `scripts/update_features.py`）を1ファイル作成する。
3. Clineがターミナルで `python3 scripts/update_features.py` を実行する。
4. Clineが `git diff` および `git status` で差分を検証し、意図通りの変更が行われたことを確認して完了する。

---

## **🔄 第6章：Phase D - ログ解析とリカバリー・ループ (Feedback Loop)**

実行エラーや意図しない差分が生じた場合、司令塔へログをフィードバックして迅速に解決します。

### **🛠️ 手順**
1. Clineが出力したエラーログや差分サマリーをコピーする。
2. 司令塔（Web版 Gemini）に対し、以下のテンプレートを用いて解析を依頼する。

```text
【ログ解析と次なる一手依頼】
Clineの実行結果ログです。現状の分析を行い、日本学術会議2025年版規格およびガイドラインに準拠したリカバリー指示（Cline向け指示書）を策定してください。
【実行ログ】：[ログの内容をペースト]
```

3. 提示された指示書をClineへ再投入し、問題を確実に解消する。

## **⚙️ 【必須セットアップ】プロジェクトルート構成定義**

本フローを正常稼働させるため、以下の構成ファイルをルート直下に配置します。

### **.clinerules (AI全般への絶対遵守事項定義)**
- **0. モード別行動規範**: Actモードによる確実かつ最小限の差分適用。
- **1. 破壊なき進化 (Zero-Modification)**: 既存のHTML構造、CSS、D3.js描画ロジック、計算アルゴリズムは指定がない限り1文字も変更しない。
- **2. ガイドラインの絶対的優先**: `docs/guideline.md` を唯一の正解基準として完全遵守。
- **3. 用語規格の死守**: 日本学術会議（2025年版）に基づく用語の厳格な区別。
